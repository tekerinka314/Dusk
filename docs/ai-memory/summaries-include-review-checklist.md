Каждый раз, когда подвожу итог проделанной работы, давать ДВА коротких списка:
**что сделано** и **что проверить в живом ревью** — кратко, но исчерпывающе (покрыть
все затронутые поведения), без воды.

**Why:** пользователь сам проверяет каждое изменение в работающем приложении; ему нужен
готовый чек-лист, чтобы ничего не пропустить.

**How to apply:** в конце слайса/задачи — таблица/буллеты коммитов+тестов (сделано) и
сгруппированный по подсистемам перечень действий для проверки (ревью). Связано с
[[7c-delegation-progress]] (там цена ошибки — регресс по делегированию).
