## ПОДТВЕРЖДЁННЫЕ НАХОДКИ

### 🔴 Критично
- **NA-1. `_grimInk()` неверная HSL→RGB ветка для 240–300° (app.js ~2040-2041).**
  Ветки `h<300` и `else` обе `rr=cc;bb=x`. Для 240–300° (фирменный фиолет!) надо `rr=x;bb=cc`.
  ДОКАЗАНО: Node + живое приложение → `#B06CF5` (270°, дефолт заметки) даёт `--nc-ink:#f36eb0`
  (розово-красный) вместо `#b06ef3`. Все фиолетовые пресеты (#9090cc,#8a5cf0,#A24BD6,#c060e0,#7B68EE)
  меняют R↔B. Фикс = одна ветка: `else if(h<300){rr=x;bb=cc;}`. Низкий риск.
  ВАЖНО (вопрос пользователя «может это намеренно для контраста?»): намеренная контраст-логика —
  это клампы L `[0.64,0.82]` и S `[0.45,0.85]` (читаемость на тёмном), их НЕ трогать. Своп каналов —
  ОТДЕЛЬНЫЙ баг в HSL→RGB реконструкции: сдвигает HUE (фиолет→розовый), а hue к контрасту отношения
  не имеет. Доказательства «баг, а не дизайн»: (1) сломан только сектор 240–300, соседние 225°/348°/160°
  корректны; (2) ветки h<300 и else идентичны = copy-paste; (3) L клампится ДО распределения по секторам →
  у buggy `#f36eb0` и fixed `#b06ef3` ОДИНАКОВАЯ светлота → контраст идентичен, разница лишь в тоне.
  Фикс контраст НЕ ослабляет. Опционально на внедрении: before/after свотчи для глазной проверки.

- **NA-2. Тело заметки рендерится/обрабатывается СЫРЫМ (несколько innerHTML-стоков).**
  Стоки: `renderGrimDetail` активный вид `bo.innerHTML=note.body` (app.js:2172, склеп на 2112
  санитайзит); `_grimPlain` (2723); `_grimFlattenSnippet` (2738); экспорт `_grimHtmlToMd`.
  Живой PoC: `<img onerror>` в теле сработал ПРИ ЗАГРУЗКЕ СПИСКА (генерация сниппета на detached-div),
  даже без открытия записи; для склепа санитайз детального вида не спасает (сниппет сырой).
  Инвариант «body всегда санитайзен» держится только для записей, созданных в приложении;
  импорт-JSON (ветка «Заменить», `...loaded`), ручной LS и БУДУЩИЙ SYNC дают сырой body.
  **Root cause + фикс:** санитайзить ВСЕ тела один раз на границе данных — в `migrateNotes()`
  (уже итерирует все notes/notesArchive) или `normalizeState()`, через существующий `_grimSanitize`.
  Дёшево, низкий риск. Делаем сейчас. Критично для roadmap-синка (облачный файл = внешний ввод).

- **NA-3. Летопись («Летопись», `grimVersions`) НЕ в export → теряется при переносе устройства.**
  `exportData` (app.js:12295) = `JSON.stringify(state)`; версии в отдельном ключе
  `dusk_note_versions_v1` (K_NOTE_VERSIONS), вне state. Конфликт с правилом №1 «не терять данные».
  Фикс: экспортировать `{...state, _grimVersions:grimVersions}` (или влить версии в note.versions
  на экспорт) + восстановить при импорте/replace. Учесть при формате облачного файла синка.

### 🟠 Важно
- **NA-4. `grimToggleCollapse` слушает `transitionend` по несуществующему свойству + утечка (app.js:1729).**
  Проверка `ev.propertyName==='grid-template-columns'`, но `.grim-layout` = `display:flex`
  (style.css:6222); анимируются `flex-basis` (.grim-list, 6565) и `gap` (layout). Грид-свойство
  не транзишенится → (а) пост-reflow таблиц-оверлея после разворота не выполняется; (б) слушатель
  НИКОГДА не снимается → накопление на каждый un-collapse. Root cause: миграция grid→flex,
  JS-гард остался от grid. Фикс: слушать `flex-basis`/`gap` (или once+fallback-таймер).

- **NA-5. Заметки переигрывают ПОЛНУЮ entrance-анимацию списка на каждую мутацию (нет renderListOnly).**
  `renderNotes`→`renderGrimList(!prefersReducedMotion())` с animate=true; путь дёргается на
  pin/цвет/архив/restore/delete/bulk. Живой замер (движение вкл): после pin 5/5 лифов получают
  `gl-in` (полный рестаггер); то же при смене цвета. У задач решено: `renderListOnly()`+`_newTaskIds`.
  Фикс: grimuar-аналог частичного рендера (патч одного лифа без рестаггера) ИЛИ гейтить gl-in
  только для реально новых записей (набор «новых note id», как `_newTaskIds`). Cross-app паритет.

- **NA-6. Merge-импорт теряет `noteTemplates` и `notesSort` (app.js:5553-5560).**
  Ветка «Добавить» тянет только `loaded.notes`/`loaded.notesArchive`. «Заменить» ок (`...loaded`).
  Фикс: домерживать шаблоны заметок (dedupe by id) и брать notesSort при отсутствии локального.

- **NA-7. Раскол модели id: задачи — int счётчики (nextId/nextGroupId/nextSubId), заметки — uuid.**
  Заметки УЖЕ в целевом состоянии (uid()=crypto.randomUUID). Хрупкая offset-арифметика merge-импорта
  (app.js:5520-5548) существует только из-за int-id задач. = отложенная Idea 8 (gated). Зафиксировать:
  мигрировать нужно ТОЛЬКО задачи; заметки готовы.

- **NA-8. «Летопись» и часть поповеров — мимо единого modal-controller (U-1/U-2).**
  `grim-hist-ov` (app.js:1537+) — самодельный оверлей со своим Esc (1638): нет focus-trap/возврата
  фокуса/общей exit-аним/aria. Аналогично поповеры таблицы/каллаута/io/tpl — свой outside-click
  вместо реестра `_gothicPickers`. Фикс: подвести историю под openModalWithFocus/closeModalWithAnim
  (или хотя бы focus-trap), поповеры — под общий outside-click. Консистентность/доступность.
