Когда я собираю **HTML-превью / мокап-файл** для ревью пользователем (кандидаты
иконок, варианты UI) — **НЕ скриншотить его самому** через headless-харнесс. Это
трата токенов: в статичном превью я всё равно не замечаю визуальных ошибок,
пользователь сам открывает файл и смотрит. Просто сгенерить HTML и дать путь
(`file:///D:/tmp/pw/...`).

**Почему:** прямой фидбек пользователя 2026-06-21 («не скриншоть html превью, ты
всё равно не замечаешь там ошибок»).

**Как применять:** сделать превью-HTML → отдать путь → ждать его ревью. НО харнесс
по-прежнему нужен для проверки **функциональных/реальных** изменений в самом
приложении (это другое — см. [[dusk-headless-screenshot]]): там клики/состояние/
замеры реально ловят баги, и это не «статичный мокап».
