## ПОДТВЕРЖДЁННЫЕ БАГИ (приоритет реализации)

### 🔴 C-1 — DnD групп-секций рушит порядок при отфильтрованном списке
- Где: `initGroupDnD()` → `sortableGroupSections.onEnd` (app.js ~6209). Делает
  `state.groups.splice(oldIdx,1); splice(newIdx,0,moved)` по **DOM-индексам**.
- Причина: `renderTasks` пропускает пустые группы в Today-mode (`if(grouped.length===0)return;` ~5226)
  и при поиске (`if(query&&grouped.length===0&&bf>0)return;` ~5219) → секции = подмножество state.groups
  → DOM-индекс ≠ индекс стейта → переставляет НЕ те группы. Тихо, БЕЗ undo.
- Pill-бар (`renderGroupBar` 6330) рисует ВСЕ группы всегда → безопасен.
- Фикс: переставлять по id (`section.dataset.groupId`), не по индексу; + `pushUndo()`.
  Либо блокировать drag секций при неполном наборе.

### 🔴 C-2 — Пустое состояние vs «Все задачи выполнены» (ложное сообщение)
- Где: `updateVisibility` (~12376), `showAllDone` (~12433).
- При фильтре ON + все задачи done: `noVisible=true` → показывает `#empty-state`
  («Нет задач. Добавьте первую.») — ложь. Плашка `#all-done` показывается лишь транзитно
  после последнего чека и сбрасывается любым render() → после перезагрузки видно «нет задач».
  Дополнительно: сразу после чека обе плашки могут показаться ОДНОВРЕМЕННО.
- Фикс: в `updateVisibility` различать «реально пусто» vs «все done, скрыты фильтром»:
  `state.tasks.length>0 && все done` → показывать `#all-done`, не `#empty-state`.
- Совместить с cross-app: дать `#empty-state` кнопку «Добавить первую задачу» (как `_grimEmptyHTML`).

### 🟠 V-1 — drag-наследование приоритета нарушает инвариант приоритет↔цвет
- Где: `applyPriorityInheritance` (~11825) ставит `task.priority=newPrio` БЕЗ сброса `task.color`.
- Модалки соблюдают: prio→`task.color=null` (~9790), color→`task.priority=null` (~9920).
- Фикс (по решению 1): единые сеттеры; drag вызывает `setTaskPriority` → он стирает цвет.
