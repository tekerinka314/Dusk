## Что сделано (закоммичено + запушено)
- **DnD заметок (f70ce0c)** — ручной порядок через SortableJS, ГИБРИД: поле `note.ord` в пространстве
  `updatedAt`, drag фиксирует, правка заметки `delete note.ord` → всплывает наверх. Только активный
  сегмент вне поиска/мультивыбора.
- **Ctrl+Z Часть 1 (3e0d960)** — фикс ПОТЕРИ ДАННЫХ: глобальный keydown перехватывал Ctrl+Z даже в
  `#grim-body`/`#grim-title-in` → app-undo удалял черновик. Теперь в редакторе гримуара Ctrl+Z/Y отдаются
  нативному undo браузера. Узкий скоуп — форма задач не тронута.
- **Ctrl+Z Часть 2 inserts-only (6fa9006)** — вставка таблицы/hr/инлайн-кода через `execCommand('insertHTML')`
  → нативный undo. Трансформации (списки/index-ops/чек-лист/снятие ссылки) ОСТАЛИСЬ без keyboard-undo
  (отложено, нужен кастомный in-body стек — см. план «ЧТО НЕ СДЕЛАНО»).

## Ключевые технические уроки (НЕ забыть в след. раз)
1. **execCommand + headless = нужен реальный user-gesture.** Без `await pg.locator('#grim-body').click()`
   (или keyboard) `document.execCommand(...)` возвращает **false** и НИЧЕГО не делает — `bo.focus()` внутри
   `pg.evaluate` НЕ активирует документ. Я из-за этого ошибочно решил «insertHTML негоден для трансформаций»
   и откатил рабочий код. ВСЕГДА кликать body перед проверкой execCommand-пути.
2. **execCommand insertHTML** надёжно вставляет в каретку (в т.ч. блочные `<table>`/`<hr>`) И это попадает
   в нативный undo-стек → Ctrl+Z откатывает целиком. Whole-body replace (selectAll/innerHTML+insertHTML)
   для мульти-блочной ЗАМЕНЫ — НЕ проверен с жестом, считать ненадёжным до проверки.
3. **Undo задач** = `undoStack` хранит `JSON.stringify(state)` целиком; `undo()`/`redo()` уже зовут
   `renderNotes()` + сбрасывают `currentNoteId` если заметка исчезла. Т.е. инфраструктура заметки покрывает,
   вопрос только «зовёт ли мутация `pushUndo`».
4. **Heredoc в Bash съедает `\\`** в путях — JS-тест-файлы писать через Write, не через bash heredoc.
