Сворачивание открытой заметки (`grimToggleCollapse`) ужимает `.grim-detail` до ~0 ширины через flex (список → flex-basis 100%). Тяжёлое тело (`.grim-body`) при этом **переверстывает весь текст** под новую ширину — O(размера тела), до 1–2 с на больших заметках, и обратно на разворот.

**Рабочее решение (вариант 3, коммит e373748):** перед сворачиванием пинить `.grim-page` `style.width` в px (`getBoundingClientRect().width`) → тело держит фикс-ширину и НЕ реверстается ни разу. Класс `.grim-detail.grim-pin { overflow:hidden }` клипает фикс-широкую страницу в узкую панель (иначе торчит вправо во время разворота, т.к. на разворот класс collapse снят и overflow пропадает). Пин и класс снимаются в `finish()` на settle разворота (натуральная ширина == пину → reflow нет). Порога по размеру нет — пин для всех, мелким безвреден. **Проверка:** ширина тела держится константой весь цикл (замер: 459–461px) → артефакт «вертикальной линии» невозможен.

**Отвергнуто:**
- **content-visibility:auto на детях `.grim-body`** — даёт −40% к reflow, НО ломает прыжки по оглавлению (TOC): невиданные секции оцениваются неверным intrinsic-size, `scrollIntoView` промахивается на десятки тысяч px (22779 vs −715). `auto`-intrinsic помнит размер только после первой отрисовки.
- **snap (transition:none для тяжёлых)** — убрал маскирующее затухание → стало ВИДНО, как тело выстраивается в вертикальную линию справа от контейнера; задержку не лечит (reflow всё равно есть). Откатил (7fa75d9).
