С 2026-06-28: после законченного куска работы (правка готова + тесты зелёные) **коммитить И пушить СРАЗУ, без отдельного спроса**.

**Почему:** обновления у пользователя теперь прилетают только через push на GitHub Pages (network-first SW). Деплой = push. Ждать ручного «коммить» тормозит доставку обновлений. Пользователь прямо потребовал автоматизировать.

**Как применять:**
- Закончил осмысленную единицу работы + прогнал регресс → `git commit` (трейлер `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`) + `git push origin refactor/sync` в том же шаге, не спрашивая.
- НЕ дробить на микрокоммиты ради коммита; коммитить логически завершённое.
- Сомнительные/рискованные/визуально-субъективные правки он всё равно смотрит живьём — но это ПОСЛЕ пуша (он ревьюит уже задеплоенное), не блокирует пуш.
- **Бамп `version.js` (BUILD) — часть КАЖДОГО коммита-деплоя** (иначе тост «доступно обновление» не сработает у сидящего на странице). Это моя строчка в чек-листе, не пользователя.

Отменяет ограничение «commit/push ONLY on his command» из [[commit-means-push]] и из CLAUDE.md. «коммить»/«комить» всё ещё = commit+push (как было), просто теперь не обязателен как триггер.
