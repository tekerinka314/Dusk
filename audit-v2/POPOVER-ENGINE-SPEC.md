## Проблема (из FINDINGS)

4 независимых движка позиционирования, все body-portal, все замеряют координаты
ОДИН раз при открытии:

| Движок | Место | Семьи |
|---|---|---|
| `_openFloatMenu` | 03-render:~1018 | snooze, task-more, sub-mode ×2, demote, export, sync-панель |
| `toggleSortPicker` | 03-render (portal) | сорт-портал |
| `_qaRenderMenu` | 08-quickadd:~156 | quick-add typeahead |
| `registerGothicPicker` | 03-render:~1733 | готические пикеры (месяц/день/группа) |

Симптомы: колёсный скролл отрывает поповер от якоря (доказано live: top 725→725
после wheel 300px); Esc не закрывает float-меню; `role="menu"` без клавиатурной
навигации; нет single-open между семьями.

## Дизайн-решение

ОДИН модульный утилитарный слой **геометрии + жизненного цикла**. Скины семей
НЕ трогаются — движок не знает, как поповер выглядит, только ГДЕ он и КОГДА
умирает. Это сознательно НЕ компонент, а «аренда позиции».

### API

```js
// 01-core или новый dusk/xx-popover.js (globalThis-бридж как у всех)
anchorPopover(el, anchorEl, {
    place: 'below',        // 'below' | 'above' | 'auto' (default 'auto': низ, флип если не влезает)
    align: 'start',        // 'start' | 'end' | 'center' — горизонтальная привязка к якорю
    margin: 8,             // px зазор от якоря и от краёв вьюпорта
    onClose: fn,           // единственный колбэк; движок вызывает, хозяин прячет/убирает DOM
    navRoot: null,         // el с role=menu → движок ведёт стрелочную навигацию по [role=menuitem]
    closeOnScroll: false,  // true → закрыть при первом скролле (вместо следования)
})  // → { close(), reposition() }
```

### Поведение (нормативное)

1. **Позиция**: замер якоря `getBoundingClientRect`, поповер `position:fixed`.
   Вертикаль: предпочесть `place`; если не влезает — флип; если не влезает и
   там — та сторона, где больше места, + `maxHeight` = доступное место − margin,
   `overflow-y:auto` (тонкий скроллбар — уже есть паттерн `.demote-menu`).
2. **Горизонталь**: `align` к якорю, затем clamp в `[margin, vw − margin]`.
   НИКОГДА не за экраном (фикс мобильного сорт-дропдауна из O-2 обязан
   сойтись с этим же поведением).
3. **Скролл/резайз**: подписка `scroll` (capture, чтобы ловить вложенные
   скроллеры) + `resize`, батч через rAF: по умолчанию — РЕПОЗИЦИЯ (поповер
   следует за якорем). Якорь ушёл из вьюпорта (rect полностью вне) — close().
   `closeOnScroll:true` — для тач-семей, где сейчас outside-pointerdown уже
   закрывает (сохранить текущее ощущение).
4. **Esc** закрывает верхний открытый (стек), фокус возвращается на якорь.
5. **Single-open**: модульный реестр; `anchorPopover()` закрывает предыдущий
   ЛЮБОЙ семьи (кроме вложенных: пикер внутри модалки живёт со своей модалкой —
   реестр слоёв: modal-слой отдельно от popover-слоя).
6. **Outside pointerdown** — close (как сейчас), pointerdown на якоре — toggle
   без повторного открытия.
7. **Клавиатура** (если navRoot): ↑/↓ по `[role=menuitem]:not([disabled])` с
   wrap, Home/End, Enter/Space = click, Tab = close + натуральный переход.
   `aria-expanded` на якоре ведёт движок.
8. **Reduced motion / скины**: движок не анимирует; семьи держат свои
   появления. Единственное «движение» движка — обновление transform при
   репозиции (мгновенное).

### Принятие по движкам (порядок — от простого)

1. `toggleSortPicker` — эталонная адаптация (уже портал; largest bug surface на
   мобиле).
2. `_openFloatMenu` — вся float-семья разом (это снимает B1-27/28 и Esc-долг).
   `navRoot` включить: у них уже `role="menu"`.
3. `_qaRenderMenu` — typeahead: `closeOnScroll:false`, навигация УЖЕ своя
   (не ломать; navRoot НЕ передавать).
4. `registerGothicPicker` — пикеры в модалках: слой modal, single-open в
   пределах слоя.

### Тесты (Opus, обязательные)

- Перезапуск s2_fix2-пробы отрыва: wheel 300px → поповер ЛИБО следует
  (top меняется на −300), ЛИБО закрыт — по семье. Все 9 поповеров.
- Esc закрывает каждый; фокус на якоре после закрытия.
- Мобильные вьюпорты 360/390: ни один поповер не пересекает край экрана
  (перекрывает O-2.1).
- Cross-family single-open: открыть snooze → открыть сорт — snooze закрыт.
- vitest без регрессий; никакой логики state не затронуто.

### Не входит (по решению)

- Перескин поповеров (B2-01) — отдельно, поверх движка.
- Anchor positioning API / @floating-ui — нет: зависимость ради 100 строк
  геометрии, а CSS anchor-positioning ещё не baseline на целевых девайсах.
